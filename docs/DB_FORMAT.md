# Формат базы хешей

База — текстовый файл в кодировке байтов (пути хранятся как есть), строки заканчиваются `\n`.

```
HASHWATCH 1
<sha256-hex> <размер> <mtime> <относительный путь>
<sha256-hex> <размер> <mtime> <относительный путь>
...
MAC <hmac-sha256-hex>        либо        END
```

## Строки

1. **Заголовок** — `HASHWATCH 1` (магическая строка + версия формата).
2. **Записи** — по одной на файл, отсортированы по пути (побайтово, `strcmp`):
   * `sha256-hex` — 64 hex-символа, SHA-256 содержимого файла;
   * `размер` — размер файла в байтах (десятичное число);
   * `mtime` — время изменения, Unix-секунды (справочно);
   * путь — всё до конца строки, относительно проверяемого каталога, разделитель `/`. Пробелы в пути допустимы.
3. **Футер** — последняя строка:
   * `MAC <64 hex>` — HMAC-SHA256 (RFC 2104), вычисленный по **всем байтам до футера**
     (включая заголовок и последний `\n` перед футером);
   * `END` — база не защищена.

## Правила проверки при загрузке

1. Если футер `MAC ...` и ключ не передан → ошибка (`DB_ERR_NEEDKEY`).
2. Если футер `END`, а ключ передан → ошибка (`DB_ERR_NOMAC`): злоумышленник не должен
   иметь возможность «снять» защиту, подменив базу на незащищённую.
3. Если футер `MAC ...` — MAC пересчитывается и сравнивается **за постоянное время**
   *до* разбора записей. Несовпадение → ошибка (`DB_ERR_MAC`).
4. Только после этого тело разбирается; любое отклонение от формата → `DB_ERR_FORMAT`.

## Запись

База пишется во временный файл `<база>.tmp` с правами `0600`, затем атомарно
переименовывается (`rename`), поэтому оборванная запись не портит существующую базу.

## Версионирование

Первая строка содержит номер версии. При несовместимых изменениях формата номер
увеличивается, старые версии утилиты отклоняют такие базы как повреждённые.
