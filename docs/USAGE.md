# Руководство пользователя

## Команды

```
hashwatch init   <каталог> -d <база> [-k <ключ>] [-f]
hashwatch check  <каталог> -d <база> [-k <ключ>] [-q]
hashwatch update <каталог> -d <база> [-k <ключ>]
hashwatch --help | --version
```

| Команда  | Что делает |
|----------|------------|
| `init`   | Обходит каталог рекурсивно, считает SHA-256 каждого обычного файла и записывает базу. Не перезаписывает существующую базу без `-f`. |
| `check`  | Сравнивает текущее состояние каталога с базой и печатает отличия. База **не** меняется. |
| `update` | То же, что `check`, но после отчёта записывает в базу новое состояние (принять изменения как легитимные). |

| Опция | Описание |
|-------|----------|
| `-d <база>` | Путь к файлу базы (обязательно). Может лежать внутри проверяемого каталога — она будет исключена из учёта. |
| `-k <ключ>` | Файл с ключом HMAC. Если указан — база подписывается (`init`/`update`) или проверяется (`check`/`update`). |
| `-f`        | `init`: перезаписать существующую базу. |
| `-q`        | `check`: печатать только итоговую строку. |

## Формат вывода

```
MODIFIED: docs/readme.txt
NEW:      tmp/new.bin
DELETED:  old/config.ini
Summary: 1 modified, 1 deleted, 1 new, 42 unchanged
```

Строки отсортированы по пути. `MODIFIED` — изменилось содержимое (отличается SHA-256).

## Коды возврата

| Код | Значение |
|-----|----------|
| 0   | Изменений нет |
| 1   | Найдены изменённые / удалённые / новые файлы |
| 2   | Ошибка: неверные аргументы, нет базы, неверный ключ или подделанная база, часть файлов не удалось прочитать |

Благодаря кодам возврата утилиту удобно использовать в скриптах и cron:

```sh
hashwatch check /etc -d /var/lib/hashwatch/etc.hwdb -k /root/hw.key -q \
  || mail -s "Изменения в /etc" admin@example.com < /dev/null
```

## Примеры

Создать защищённую базу для `/etc`:

```sh
head -c 32 /dev/urandom > hw.key && chmod 600 hw.key    # ключ: храните отдельно от базы!
sudo hashwatch init /etc -d /var/lib/hashwatch/etc.hwdb -k hw.key
```

Проверить:

```sh
sudo hashwatch check /etc -d /var/lib/hashwatch/etc.hwdb -k hw.key
```

После планового обновления системы принять новое состояние:

```sh
sudo hashwatch update /etc -d /var/lib/hashwatch/etc.hwdb -k hw.key
```

## Что учитывается и что нет

* Учитываются **обычные файлы**. Символические ссылки, сокеты, устройства пропускаются.
* Сравнение — только по содержимому (SHA-256). Размер и время изменения хранятся в базе справочно.
* Права доступа и владелец не отслеживаются.
* Файлы, в имени которых есть символ перевода строки, пропускаются с предупреждением (и код возврата станет 2).
* Платформы: Linux, macOS, BSD (POSIX). Windows — через WSL.
