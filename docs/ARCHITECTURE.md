# Архитектура

## Назначение

`hashwatch` — консольная утилита, которая:

1. строит базу хешей (SHA-256) файлов каталога (`init`);
2. сравнивает текущее состояние каталога с базой и сообщает об **изменённых, удалённых и новых** файлах (`check`, `update`);
3. при желании защищает саму базу от подделки с помощью HMAC-SHA256.

## Стандарты

| Стандарт | Где используется |
|----------|------------------|
| **FIPS 180-4** (Secure Hash Standard) | `src/sha256.c` — реализация SHA-256 «с нуля», без внешних библиотек |
| **RFC 2104** (HMAC) | `src/hmac.c` — HMAC поверх SHA-256; подпись базы в `src/db.c` |
| RFC 4231 | тестовые векторы HMAC-SHA256 (`tests/test_hmac.c`) |

## Модули

```
            +-----------+
            |  main.c   |  разбор аргументов, команды init/check/update, коды возврата
            +-----+-----+
      +-----------+------------+----------------+
      v           v            v                v
  +--------+  +--------+   +---------+     +--------+
  | scan.c |  |  db.c  |   | diff.c  |     | entry.c|  список записей (путь, хеш, размер, mtime)
  +---+----+  +---+----+   +---------+     +--------+
      |           |
      v           v
  +----------+  +----------+
  | sha256.c |  | hmac.c   |--> sha256.c
  +----------+  +----------+
        hexutil.c  (hex-кодирование, сравнение за постоянное время)
```

| Модуль | Ответственность |
|--------|-----------------|
| `sha256.[ch]`  | SHA-256: потоковый API (`init/update/final`), `sha256_file` |
| `hmac.[ch]`    | HMAC-SHA256: потоковый и однократный API |
| `hexutil.[ch]` | `hex_encode`, `hex_decode`, `ct_equal` |
| `entry.[ch]`   | динамический массив записей, сортировка по пути |
| `scan.[ch]`    | рекурсивный обход каталога (`opendir`/`lstat`), хеширование обычных файлов, исключение файла базы по `dev/ino` |
| `db.[ch]`      | сериализация/разбор базы, MAC, атомарная запись (см. [DB_FORMAT.md](DB_FORMAT.md)) |
| `diff.[ch]`    | слияние двух отсортированных списков → `MODIFIED` / `DELETED` / `NEW` за O(n) |
| `main.c`       | CLI |

Вся логика находится в библиотеке (всё, кроме `main.c`), поэтому каждый модуль
покрыт собственным unit-тестом.

## Алгоритм `check`

1. Загрузить базу; если есть MAC — проверить (ошибка → код 2, до какого-либо разбора).
2. Обойти каталог, посчитать SHA-256 всех обычных файлов, отсортировать пути.
3. Слить два отсортированных списка:
   * путь только в базе → `DELETED`;
   * путь только на диске → `NEW`;
   * путь в обоих, хеши различаются → `MODIFIED`.
4. Напечатать итог; код возврата 0 (нет изменений) / 1 (есть) / 2 (ошибка).

## Модель угроз

**Защищает от:** незаметной модификации, удаления или подбрасывания файлов в наблюдаемом каталоге.

**HMAC добавляет защиту от:** подмены самой базы. Злоумышленник, изменивший файлы, не может
пересчитать базу, не зная ключа. Понижение защиты (замена базы на версию без MAC) отклоняется.

**Не защищает от:**

* злоумышленника, который получил доступ к ключу (храните ключ отдельно от базы и от проверяемой системы, либо на внешнем носителе);
* злоумышленника, подменившего сам бинарник `hashwatch` — запускайте проверенную копию;
* изменений, произошедших и откатившихся между двумя проверками;
* гонок (TOCTOU) между обходом и чтением файла: каталог не «замораживается» на время проверки;
* изменений метаданных (права, владелец, xattr), так как отслеживается только содержимое.

Без ключа (`-k`) база защищена только правами доступа к файлу: она обнаруживает случайные
изменения и работу «неаккуратного» нарушителя, но не целенаправленную подделку.

## Решения и компромиссы

* **Свой SHA-256 вместо OpenSSL** — проект учебный, нужна реализация по FIPS 180-4 и отсутствие зависимостей. В продакшене стоит использовать проверенную библиотеку.
* **Текстовый формат базы** — читается глазами, удобно диффить и отлаживать.
* **MAC проверяется до разбора** — разбор данных, не прошедших аутентификацию, не выполняется.
* **Сравнение только по хешу** — mtime легко подделать, а при совпадении хеша содержимое одинаково.
